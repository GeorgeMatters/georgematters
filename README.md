# George Matters

Static site for the Austrian musician George Matters, built with Astro.
All editable content lives in **one** YAML file; everything else is derived from it.

## Requirements

Node **22+**. Astro refuses to run on anything older, so *every* npm script
fails until you switch — this is the most common reason the project appears
broken.

`.nvmrc` pins the version but **nvm does not apply it automatically**. Run this
once per terminal session, from the project directory:

```bash
nvm use
```

To stop having to remember it, make 22 your default (this machine currently
defaults to Node 20):

```bash
nvm alias default 22
```

Then:

```bash
npm ci
npm run dev      # dev server
npm run build    # production build into dist/
npm run preview  # serve the built site
npm run check    # guards + build + secret scan (what CI runs)
```

`predev` / `prebuild` / `prepreview` run a version check first and print the
exact fix rather than a generic engine error.

## Editing content

`src/data/content.yaml` is the single source of truth for everything an owner can
change: contact details, opening copy, services, projects, gallery, footer and
legal-facing text.

The file is validated against a Zod schema (`src/lib/content.ts`) on every build.
The schema is **strict**, so:

- a typo in a field name fails the build (unrecognized key)
- an unknown icon name or gallery `size` fails the build
- a malformed e-mail or URL fails the build
- an image path that does not exist under `src/assets/images/` fails the build

Component prop types are derived from that schema with `z.infer` — they are never
written by hand, so they cannot drift from what is validated.

### Adding an image

1. Put the file in `src/assets/images/`.
2. Reference it from `src/data/content.yaml` as `images/<filename>`.

Astro generates the responsive variants, modern formats and intrinsic dimensions.
Do not put content images in `public/` — that bypasses the pipeline.

## Structure

| Path | Purpose |
|---|---|
| `src/data/content.yaml` | all editable content |
| `src/lib/content.ts` | Zod schema, validation, derived types |
| `src/lib/images.ts` | resolves content image paths, throws on a miss |
| `src/layouts/Layout.astro` | head, metadata, JSON-LD graph |
| `src/components/*` | page sections |
| `src/pages/index.astro` | composes the page |
| `src/pages/404.astro` | not-found page (noindex) |
| `src/pages/robots.txt.ts` | generated, sitemap path derived |
| `src/pages/llms.txt.ts` | generated, llmstxt.org format |
| `src/styles/global.css` | design tokens and shared UI |
| `scripts/*.mjs` | CI guards |

A sitemap index is generated by `@astrojs/sitemap` at build time into `dist/`.

## CI

| Workflow | Trigger | Does |
|---|---|---|
| `.github/workflows/ci.yml` | pull requests | guards + build |
| `.github/workflows/deploy.yml` | push to `master` | build + deploy to Pages |

Guards, both run in CI and locally:

```bash
node scripts/check-no-hardcoded-content.mjs   # business data must live in the content store
node scripts/check-no-secrets.mjs             # nothing credential-shaped in dist/
```

Third-party actions are pinned to commit SHAs; Dependabot keeps them current.

## Deployment

GitHub Pages via GitHub Actions. **The repository's Pages source must be set to
"GitHub Actions"** (Settings → Pages) or the workflow builds and publishes nothing.

## Privacy

The site loads **no** third-party resources. Fonts are self-hosted via
`@fontsource-variable`. Adding any external embed (map, video, analytics) would
require a consent gate that keeps the element out of the DOM until consent —
hiding it with CSS still issues the request.
